Утилита на Go для синхронизации групп в разделе **Маршруты DNS** на KeeneticOS 5 с Entware. Запускается из SSH или по расписанию через `cron`.

## Что делает

- Загружает выбранные списки v2fly и текстовые списки по прямым HTTPS-ссылкам. Текстовые списки могут содержать домены, IP-адреса и подсети в формате CIDR. [Списки v2fly](https://github.com/v2fly/domain-list-community)
- Создаёт недостающие группы и обновляет записи в существующих группах по `sync`. При необходимости разбивает список на части, например `Youtube 1` и `Youtube 2`, с лимитом до 300 записей на группу.
- Удаляет управляемые группы по `clean --apply`.

## Важные особенности

- Сохраняет существующие DNS-маршруты и их параметры. Настройка `routeInterface` позволяет добавлять недостающие маршруты через выбранный интерфейс.
- Настройка `ipv6: false` исключает IPv6-адреса и подсети из текстовых списков.
- `sync --dry-run` и `clean --dry-run` показывают план до применения. `validate` проверяет конфиг без обращения к роутеру и источникам списков.
- После применения утилита проверяет изменения на роутере и только потом сохраняет конфигурацию.

## Установка и обновление

Команды выполняются в SSH-терминале Entware на роутере. Доступны пакеты для ARM64 (`aarch64-3.10`) и MIPS LE (`mipsel-3.4`). Архитектуру можно посмотреть командой `opkg print-architecture`.

Перед подключением OPKG-репозитория на GitHub Pages установите `wget` с поддержкой HTTPS и корневые сертификаты. [Поддержка HTTPS в Entware](https://github.com/Entware/Entware/wiki/Using-HTTPS-with-opkg)

```sh
opkg update
opkg install ca-certificates wget-ssl
```

Если в Entware установлен `wget-nossl`, удалите его после установки `wget-ssl`.

```sh
opkg remove wget-nossl
```

Добавьте репозиторий для своей архитектуры и установите пакет. В примере выбран ARM64. Для MIPS LE замените `aarch64-3.10` на `mipsel-3.4`.

```sh
mkdir -p /opt/etc/opkg
echo 'src/gz kgs https://aaeremin02.github.io/keenetic-geosite-sync/aarch64-3.10' > /opt/etc/opkg/kgs.conf
opkg update
opkg install keenetic-geosite-sync
```

Пакет устанавливает утилиту в `/opt/bin/keenetic-geosite-sync` и подтягивает `ca-bundle` для проверки сертификатов при загрузке списков.

Для ручной установки скачайте `.ipk` под свою архитектуру и скопируйте в `/opt/tmp`. Подставьте имя скачанного файла в команду. [Скачать пакет в GitHub Releases](https://github.com/aaeremin02/keenetic-geosite-sync/releases/latest)

```sh
opkg update
opkg install "/opt/tmp/ИМЯ_ФАЙЛА.ipk"
```

Для обновления через репозиторий выполните следующие команды.

```sh
opkg update
opkg upgrade keenetic-geosite-sync
```

При обновлении сохраняется существующий `config.json`.

## Настройка

Установщик создаёт `/opt/keenetic-geosite-sync/config.json` с содержимым `{}`, если файла ещё нет. Добавьте списки, которыми должна управлять утилита. Пример синхронизирует YouTube, Google Play и IPv4-подсети Telegram.

```json
{
  "routeInterface": "Wireguard0",
  "ipv6": false,
  "lists": [
    {
      "source": "v2fly",
      "lists": ["youtube", "google-play"]
    },
    {
      "source": "plain",
      "name": "Подсети Telegram",
      "url": "https://core.telegram.org/resources/cidr.txt"
    }
  ]
}
```

### Источники списков

Верхний массив `lists` содержит настройки источников. В него можно одновременно добавить несколько списков v2fly и несколько текстовых файлов по HTTPS. Каждый пример ниже представляет один элемент этого массива.

#### `v2fly` — списки из `domain-list-community`

```json
{
  "source": "v2fly",
  "lists": ["youtube", "google-play"]
}
```

- `source` со значением `v2fly` выбирает встроенный адрес репозитория.
- В `lists` перечислите имена файлов из каталога `data`. Утилита синхронизирует каждый список отдельно и делает первую букву его имени заглавной. Например, из `youtube` и `google-play` получатся подписи `Youtube` и `Google-play`. [Каталог списков v2fly](https://github.com/v2fly/domain-list-community/tree/master/data)

При загрузке утилита раскрывает вложенные `include:` и учитывает их фильтры по атрибутам. Правила `keyword` и `regexp` пропускаются.

#### `plain` — текстовый список по HTTPS

```json
{
  "source": "plain",
  "name": "Cloudflare IPv4",
  "url": "https://www.cloudflare.com/ips-v4/"
}
```

- `source` со значением `plain` выбирает загрузку обычного текста.
- `name` задаёт подпись группы в интерфейсе Keenetic. Выбирайте уникальную подпись среди всех источников. Например, `Youtube` и `youtube` считаются одним именем.
- `url` задаёт прямую HTTPS-ссылку, по которой сервер отдаёт содержимое списка.

В одном файле можно смешивать домены, отдельные IP-адреса и подсети в формате CIDR. Указывайте по одной записи на строку. Пустые строки и текст после `#` пропускаются.

```text
# Пример содержимого файла
example.org
192.0.2.10
198.51.100.0/24
2001:db8::/32
```

### Общие параметры

Массив `lists` и общие параметры задаются на верхнем уровне `config.json`. Внутри элементов `lists` указываются поля конкретных источников.

- **`lists`** — источники, которыми управляет утилита. По умолчанию массив пуст. `sync` обновляет группы для указанных списков, а `clean` выбирает группы для удаления по этому же набору. Если убрать источник из конфига, его группа останется на роутере.
- **`prefix`** — начало внутреннего имени группы. По умолчанию `domain-list`, поэтому новые имена выглядят как `domain-list0` и `domain-list1`. Для поиска существующей группы утилита проверяет и префикс, и видимую подпись. Например, с `"prefix": "kgs-"` она будет работать с группами `kgs-0`, `kgs-1` и так далее, а группы `domain-list…` останутся на роутере.
- **`routeInterface`** — интерфейс для добавления недостающих DNS-маршрутов ко всем указанным спискам. Например, `"routeInterface": "Wireguard0"` добавит маршрут через этот интерфейс для групп, у которых его ещё нет. Существующие маршруты сохраняются. По умолчанию поле пустое, и дополнительный интерфейс из конфига не назначается. Сами списки загружаются по системному маршруту роутера.
- **`maxEntriesPerGroup`** — сколько записей помещать в одну группу. Допустимы значения от 1 до 300, по умолчанию 300. Например, 450 записей для YouTube разделятся на `Youtube 1` с 300 записями и `Youtube 2` со 150. При значении 200 для того же списка получится три группы.
- **`timeoutMs`** — максимальное время одной попытки скачать файл, включая чтение ответа сервера. По умолчанию 20 000 мс (20 секунд). Например, `"timeoutMs": 30000` даст каждой попытке до 30 секунд.
- **`retries`** — максимальное число попыток загрузить один файл, включая первую. По умолчанию `3`, то есть первая попытка и до двух повторов при временных сбоях. Значение `1` оставит одну попытку. Если сервер возвращает `404`, загрузка завершается сразу.
- **`ipv6`** — включает IPv6-адреса и подсети из источников `plain`. По умолчанию `true`. При `false` IPv6-записи пропускаются при загрузке и удаляются из управляемых групп при следующей успешной синхронизации. Если в списке после фильтрации не осталось пригодных записей, синхронизация остановится с ошибкой до применения изменений.
- **`dryRun`** — включает предварительный просмотр для `sync` и `clean` при запуске с этим конфигом. По умолчанию `false`. При `true` даже обычный `sync` и `clean --apply` только показывают план. Для разовой проверки добавьте `--dry-run` при запуске.

Проверить формат конфига, имена и дубликаты групп, а также синтаксис HTTPS-ссылок можно отдельно от роутера.

```sh
keenetic-geosite-sync validate --config ./config.json
```

## Синхронизация

Посмотрите план, затем примените его.

```sh
keenetic-geosite-sync sync --dry-run
keenetic-geosite-sync sync
```

Утилита ищет существующую группу по подписи и префиксу. Если группы ещё нет, она появится при применении. При пустом `lists` синхронизация не меняет группы.

Для запуска с другим конфигом используйте `sync --config /путь/к/config.json`. При ошибке применения утилита сообщает, сколько операций успело выполниться, и возвращает ненулевой код. Перед повтором посмотрите план по текущему состоянию роутера через `sync --dry-run`.

После применения утилита проверяет результат и делает до трёх попыток сохранить конфигурацию. Если сохранение не удалось, следующий запуск с применением повторит только сохранение перед новыми изменениями, пока конфигурация совпадает с проверенной. Если она изменилась, утилита сообщит об этом и пересчитает план.

## Запуск по расписанию

Установите `cron` в Entware.

```sh
opkg install cron
```

Один раз выполните команду ниже в SSH-терминале. Она добавит в конец `/opt/etc/crontab` задание для запуска от имени `root` по субботам в 04:00 по времени роутера.

```sh
echo '0 4 * * 6 root /opt/bin/keenetic-geosite-sync sync' >> /opt/etc/crontab
```

Если cron ещё не запущен, запустите его. [Документация Entware по cron](https://github.com/Entware/Entware/wiki/Using-Cron)

```sh
/opt/etc/init.d/S10cron start
```

## Очистка и удаление пакета

Чтобы удалить управляемые группы, сначала проверьте план.

```sh
keenetic-geosite-sync clean --dry-run
keenetic-geosite-sync clean --apply
```

Очистка затрагивает группы из `lists` внутри настроенного префикса. Вместе с группой могут быть удалены связанные DNS-маршруты.

Для удаления утилиты из Entware выполните `opkg remove keenetic-geosite-sync`.
